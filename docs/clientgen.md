# Typed Go clients

[Project](../README.md) · [Documentation index](README.md) · [Design](design.md#typed-go-client-clientgen)

Package `clientgen`, and the command `cmd/clientgen` that wraps it. Available Go
API; standard library plus `registry` only.

## Purpose

Turn capability descriptors into Go source that calls those capabilities with
typed inputs and outputs. The other projections serve a caller that reads
schemas while it runs: an agent, a script, an HTTP client. A compiled caller
wants the schemas as types, checked when it is built. This is the projection
for it: a program in another process, or another module, that calls
capabilities through whatever carries the call (a host's handle, HTTP), and
today hand-writes a struct for every input and output it uses.

It is not for Go code in the same process as the library it calls. That code
calls the library ([design rule 5](design.md#1-rules)).

## Features

- For each capability: a constant for its ref, an input type and an output type
  from its JSON Schemas, and a function that calls it and returns the typed
  output.
- For a capability that pages: a function that yields every page and one that
  returns every item, or every byte, of every page.
- Doc comments from the capability's title and description, field comments
  from schema descriptions, and a note on long-running capabilities.
- Generated code that imports the standard library only, and calls through a
  one-method interface it declares itself: no module requirement on this
  library, or on anything else, is added to the caller.
- Input as `registry.Descriptor` values, or as the JSON another process
  describes itself with.
- Formatted source returned as bytes, the same bytes for the same input.
  Nothing is written by the package.

## Mental model

`Generate` is a pure function from descriptors and options to files. It reads
each descriptor's `name`, `version`, `title`, `description`, `input`, `output`
and `long`, and nothing else: no view, no registry, no live state. A host that
builds a caller generates the client for exactly the capabilities that caller
requires, from the descriptors their providers published, and can key the build
by the bytes it gets.

The generated package declares one interface, and every function takes it:

```go
type Caller interface {
	Call(ctx context.Context, ref string, in any) (json.RawMessage, error)
}

func StorageArtifactGet(ctx context.Context, c Caller, in StorageArtifactGetIn) (StorageArtifactGetOut, error)
```

`Call` sends `in` as JSON to the capability `ref` names (always `name@version`)
and returns its output as JSON, waiting for it to finish. Anything with that
method is a `Caller`: the handle a host gives a provider process for calls back
through the host, twenty lines over the [HTTP projection](projections.md#http)
(the [conformance suite's](../conformance/testdata/clientgen/main.go) is one), a
`registry.View` wrapped to marshal its input, a fake in a test.

## Responsibilities and boundaries

The generator maps shapes. It does not validate values (the registry does,
once, before the handler), authenticate, retry, or interpret error codes: the
`Caller`'s error is returned as it is, so a coded error stays coded. It knows
no domain and no transport. Behaviour that is more than a shape, such as "run
this, then read that file of the result", stays hand-written, on top of the
generated functions.

## Public interfaces

```go
func Generate(descriptors []registry.Descriptor, opts Options) (map[string][]byte, error)
func ParseDescriptors(data []byte) ([]registry.Descriptor, error)

type Options struct {
	Package string   // name of the generated package; required
	Include []string // refs to generate: "name@version", or a bare name for the highest version described; empty means all
	Group   Grouping // OneFile (default) or ByNamespace
}

const Header = "// Code generated by capability-services clientgen. DO NOT EDIT."
```

- `Generate` returns file name to formatted source. Every file starts with
  `Header`. The order of `descriptors` does not matter: capabilities are written
  by name, then version. A ref in `Include` that no descriptor has is an error.
- `OneFile` puts everything in `client.go`. `ByNamespace` puts the `Caller`
  interface in `client.go` and each namespace's capabilities (the first segment
  of the name) in `<namespace>_client.go`. Grouping changes the files and never
  a name.
- `ParseDescriptors` accepts a JSON list of descriptors, or an object with the
  list under `capabilities`: the HTTP listing (`GET /v1/`) and the reply a
  provider process sends the host that asks it to describe itself. Members the
  generator does not use are ignored, so a wire form that carries fewer members
  than `registry.Descriptor` is accepted as it is.

The command, for a person at a shell (a program generates through the package):

```sh
go run github.com/craggy-io/capability-services/cmd/clientgen \
    -package hostclient -out ./internal/hostclient \
    -include artifacts.content@1,workers.do@1 -by-namespace \
    artifacts.json workers.json        # or - for standard input
```

It writes the files into `-out`, and removes a file there that an earlier run
generated and this one does not. Nothing else in the folder is touched.

## Names

A name is made by cutting the text at every character that is not a letter or
a digit, making the first letter of each piece upper case, and joining the
pieces. Nothing else changes: there is no list of initialisms, so `artifactId`
is `ArtifactId`. A result that would start with a digit gets `X` in front.

| What | Go name | Example |
| --- | --- | --- |
| Capability `artifacts.runs.record-tree@1` | the whole name | `ArtifactsRunsRecordTree` |
| Its ref, input, output | `…Ref`, `…In`, `…Out` | `ArtifactsRunsRecordTreeRef`, `…In`, `…Out` |
| Its page readers, when it pages | `…Pages`, `…All` | `ArtifactsContentPages`, `ArtifactsContentAll` |
| Several versions of one name generated together | every one carries `V<version>` | `TestVerV1`, `TestVerV2` |
| Property `postal-code` | a field | `PostalCode`, tagged `json:"postal-code"` |
| An object in property `shipping` of `…In` | parent, then field | `…InShipping` |
| An object as an array's items, a map's values | `…Item`, `…Value` | `WorkersDoInInputsItem` |
| `$defs` entry `Node` of `…Out` | root, then the entry's name | `…OutNode` |
| Enum value `in-progress` of type `…State` | type, then value (`Empty` for `""`) | `…StateInProgress` |

The namespace is part of every name, so one package holds the clients of
several providers without clashes. A version is in the name only when it has to
be: add a second version of a name to `Include` and the unversioned name stops
compiling, instead of quietly meaning the other version.

**A name derived twice is an error, never a rename.** `a.b-c` and `a.b.c`, two
properties that become one field, two enum values that become one constant, a
capability `a.b.in` beside `a.b` (whose input type is `ABIn`), or a capability
named `caller`: `Generate` fails and says which two things collide.

## From schema to Go type

| Schema | Go type |
| --- | --- |
| `object` with `properties` (or with `additionalProperties: false` and none) | a named struct. Fields are in the order of `properties` in the schema, so the struct marshals its members in the order the provider declared them. |
| property in `required` | field tagged `json:"name"` |
| property not in `required` | field tagged `json:"name,omitempty"`; an object is a pointer, because `omitempty` never leaves a struct out |
| `object` with only `additionalProperties: {schema}` | `map[string]T` |
| `object` with neither, or `additionalProperties: true` | `map[string]any` |
| `array` with `items` | `[]T` |
| `string` | `string`; `format: date-time` stays a `string`, so the text is what was sent |
| `string` with `contentEncoding: base64` (what `[]byte` is in a schema derived from a Go struct), or `format: byte` | `[]byte` |
| `string` (or no type) with an `enum` of strings | a named `string` type and a constant for each value |
| `integer`, `number`, `boolean` | `int64`, `float64`, `bool` |
| `type: [T, "null"]`, or `anyOf`/`oneOf` of a schema and `{"type": "null"}` | the type of `T` as a pointer; a slice, a map and `[]byte` stay as they are, since `nil` is their null |
| `allOf` with one member | that member |
| `$ref` to `#/$defs/Name` or `#/definitions/Name` | when the definition is a struct or a string enum, one named type however often it is referred to; otherwise the definition's type, in place |
| a struct that contains itself (`$ref` to a definition being generated, or to `#`) | a pointer where it is a field's own type; `[]T` and `map[string]T` need none |
| no input schema | an empty struct, sent as `{}` |
| a schema that is not an object with properties, as a whole input or output | an alias: `type XOut = []string` |

What has no single Go type falls back, and the type's comment says so:

| Schema | Fallback |
| --- | --- |
| no schema at all (an output that declares none, `{}`, `true`) | `json.RawMessage` |
| `oneOf`, `anyOf` (other than "or null"), `allOf` with several members | `json.RawMessage` |
| several types (`["string", "integer"]`), `type: "null"` | `json.RawMessage` |
| `array` without `items`, or with `prefixItems` (a tuple) | `[]json.RawMessage` |
| a `$ref` outside the schema, to a missing definition, or by any other JSON pointer | `json.RawMessage` |
| recursion that is not through a struct (an array definition that contains itself) | `json.RawMessage` at the point it recurs |
| an object with `properties` that also admits other members (`additionalProperties: true` or a schema, `patternProperties`) | `map[string]any`: a struct would drop the others |
| an object with a property name no struct tag can carry (a comma, a quote) | `map[string]any` |
| an `enum` of numbers, or of mixed values | the plain type, no constants |

Keywords that restrict a value without changing its type (`minimum`, `pattern`,
`const`, `not`, `if`) are not checked by the client. The registry checks them.

## Paged reads

A capability that returns its result a page at a time gets two more functions:

```go
func ArtifactsContentPages(ctx context.Context, c Caller, in ArtifactsContentIn) iter.Seq2[ArtifactsContentOut, error]
func ArtifactsContentAll(ctx context.Context, c Caller, in ArtifactsContentIn) ([]byte, error)
```

`…Pages` calls the capability page after page and yields each output. `…All`
returns the page field of every output, joined. Both send `in` unchanged with
every call apart from the field that moves, so the page size is the caller's.

Paging is detected from the descriptor alone. The input and the output must be
objects with properties, and declare one of:

| Convention | The input declares | The output declares | A page starts at | The last page |
| --- | --- | --- | --- | --- |
| Cursor: the library's own, [`registry.PageIn` and `Page`](design.md#25-pagination) | `cursor`, a string | `next`, a string | the `next` of the page before | `next` is empty |
| Offset: a window on bytes or rows | `offset`, an integer | `eof`, a boolean | `offset` plus the number of items, or bytes, of the pages before | `eof` is true, or the page is empty |

and, in both, the output must have **exactly one property that is an array or
a base64 string**: that is the page. When it has several, the one named `items`
is the page; without one named `items`, the capability is not treated as paged.
The properties must be plain (`"type": "string"`, not `["string", "null"]`).

A capability that pages and declares no output schema, or pages some other way,
gets only its plain function: write the loop on top of it.

`…Pages` stops at the first failed call and yields its error. With a cursor, a
page whose `next` is the cursor it was asked with is an error, not a page to
ask for again. `…All` holds everything in memory and has no bound of its own:
range over `…Pages` to stop early.

## Working with other packages

`clientgen` imports `registry`, for `Descriptor`, and no projection.
`View.Descriptors` and the [HTTP listing](projections.md#http) are where
descriptors come from in this module. The generated code imports none of it.
The [conformance suite](conformance.md) compiles a generated client for its
capability sets and requires every call through it to give what `Invoke`
gives.

## Examples

Compiled and checked by `go test`, in
[clientgen/example_test.go](../clientgen/example_test.go):

- `ExampleGenerate`: a client for a registry's capabilities, with the
  declarations it holds.
- `ExampleParseDescriptors`: descriptors from another process's JSON, a client
  for only the refs a caller requires, a file for each namespace, and a name
  collision reported as an error.

```go
descriptors, err := clientgen.ParseDescriptors(reply) // {"capabilities": [...]}
files, err := clientgen.Generate(descriptors, clientgen.Options{
	Package: "host",
	Include: []string{"blobs.read@1", "tools.run@2"},
	Group:   clientgen.ByNamespace,
})
// files: client.go, blobs_client.go, tools_client.go
```

and in the program that is compiled with those files:

```go
data, err := host.BlobsReadAll(ctx, caller, host.BlobsReadIn{Id: id, Limit: 65536})
out, err := host.ToolsRun(ctx, caller, host.ToolsRunIn{Tool: host.ToolsRunInToolScan})
```

The generated source for a small descriptor set, and for a real one, is under
[clientgen/testdata/golden](../clientgen/testdata/golden).

## Semantics, errors and limits

- **Long-running capabilities.** The function behaves as the `Caller` does: it
  returns when the capability has finished. There is no job handle and no
  progress. Its doc comment says so. A caller that wants a handle calls
  `jobs.*` capabilities through whatever its transport offers.
- **Errors.** The `Caller`'s error is returned unwrapped. An output that does
  not fit its type is an error that names the ref.
- **Unknown members** of an output are ignored, so a provider may add one
  without breaking a compiled caller.
- **Numbers in `any`.** The output is decoded with `UseNumber`: a number that
  lands in a `map[string]any` is a `json.Number`, the number that was sent,
  however large, and marshals back to the same text. Typed fields are
  unaffected.
- **Optional scalars are values.** A zero optional `string`, `int64`,
  `float64` or `bool` is not sent, and an absent one reads as zero: a caller
  cannot send an optional `false` or `0` explicitly, or tell an absent one
  from zero. That is what a provider whose schema comes from a Go struct means
  by optional. A schema that needs the difference declares the property
  nullable, which is a pointer.
- **`nil` is `null`.** A required slice or map that is `nil` is sent as
  `null`, as in any Go struct. Schemas derived from Go structs admit it for
  slices (`["null", "array"]`); set an empty one where a schema does not. A
  required struct that contains itself is a pointer, and `nil` is `null` too.
- **Types are per capability.** Two capabilities whose schemas have the same
  nested shape get two types: a schema carries no type names, and
  `registry.Func` expands every type in place.
- **Integers are `int64`**, whatever range the schema allows.
- **Descriptors must be generatable as a set.** One capability with a schema
  that is not JSON, or one name collision, fails the whole call: there is no
  partial output.
- Descriptor members other than the seven listed under
  [Mental model](#mental-model) (effects, tags, supersession, readiness,
  examples) do not reach the generated code. The source depends on the
  schemas, the names and the texts, and on nothing live.
- The generated code needs Go 1.23 or newer (`iter`).

## Validation and evidence

`go test ./clientgen` covers every row of the tables above on hand-written
schemas ([mapping_test.go](../clientgen/mapping_test.go)): names, collisions,
versions, `Include`, grouping, determinism, paging detection and the JSON
forms `ParseDescriptors` takes. `TestGolden` holds the output for a small
descriptor set and for the real descriptors of two provider processes
([testdata/describe](../clientgen/testdata/describe)) to golden files; refresh
them with `go test ./clientgen -update`.

`TestGeneratedCodeBehaves` writes both clients into a module that requires
nothing, with no workspace and no proxy, runs `go vet` and then the tests in
[testdata/behaviour](../clientgen/testdata/behaviour) beside them: a generated
type marshals to the bytes of a hand-written struct with the same tags, full
and empty; a value read and written again is unchanged; unknown members,
`json.Number`, both paging conventions (page requests, early exit, a failing
call, a provider that repeats its cursor) against a fake `Caller`. For the real
descriptors it checks the generated types against copies of the hand-written
client those providers' callers share today: each input goes on the wire as
that client sends it, each output is read to the same values, and `…All` over
the byte, file-range and row readers makes the same calls and returns the same
result as its hand-written loops.

`go test ./conformance` compiles a generated client for the Go and the
Starlark capability sets and runs it against a registry through the HTTP
projection ([conformance](conformance.md)). `go test ./cmd/clientgen` covers
the command. These tests run the `go` tool; a test binary run where there is
none skips them and says so.
